Three.js と TypeScript でスマホ向け3D無双ゲームを作る設計ポイント

公開日: 2026-11-21 カテゴリ: ゲーム開発・フロントエンド

ブラウザ上で3Dアクションゲームを動かす場合、最大のハードルになるのが「起動の速さ」と「スマートフォンでの操作感・フレームレート維持」です。 Unimate JP で公開している 授業中妄想クライシス と SHELTER MUSOU では、Three.js と TypeScript のシンプルな構成で爽快な無双体験を実現するために、いくつかの設計方針を徹底しました。

1. 外部3Dモデルを使わずプロシージャルなローポリで組む

GLTF/GLB などの外部3Dアセットや高解像度テクスチャを大量に読み込むと、モバイル回線では初回ロードに数秒以上かかり、ユーザーがタイトル画面を見る前に離脱してしまいます。 そこで、キャラクター・武器・教室の机や黒板・防衛タレットといった要素は、Three.js のプリミティブ（Box / Cylinder / Cone など）を組み合わせたプロシージャル・ローポリモデルとしてコード上で組み立てています。

  • 初回ロードが軽く、URLをタップして1秒前後でタイトル画面が立ち上がる
  • 武器の持ち替えやカラーバリエーションをコードから即座に反映できる
  • ポリゴン数が少ないため、数十体の敵が同時に出現してもスマートフォンで60fps近くを維持しやすい

2. マルチタッチ前提の仮想スティック＆右ボタン配置

スマホアクションでストレスになりやすいのが、「移動しながら攻撃や回避を押したら入力が途切れる」問題です。 TouchInputManager では Pointer Events の pointerId ごとにタッチを追跡し、左エリアの仮想ジョイスティックと右側のアクションボタン群、さらに画面中央のカメラ回転スワイプが互いに干渉しないよう分離しています。

また、CSS で touch-action: none とセーフエリア（env(safe-area-inset-bottom)）を適切に指定することで、iOS Safari などでプレイ中に意図せずページがスクロールしたり拡大されたりする事故を防いでいます。

3. 爽快感を決める「ヒット演出」と Web Audio 合成

ローポリのシンプルな見た目でも「殴って気持ちいい」「斬って爽快」と感じさせる鍵は、攻撃が当たった瞬間のフィードバックです。

  • ヒットストップ＆スローモーション：強い一撃やボス撃破時に数フレームだけ時間経過を遅くし、重みを演出
  • 画面フラッシュとカメラシェイク：ダメージや覚醒発動時にカメラ位置を微振動させて臨場感を強化
  • Web Audio API による効果音合成：外部MP3を読み込まずオシレーターとノイズで打撃音やアラートをリアルタイム生成
実際に動作するデモは 授業中妄想クライシス および SHELTER MUSOU からブラウザですぐ体験できます。

4. ユニットテストでゲームロジックの品質を担保する

3D描画部分は目視確認が必要ですが、当たり判定（CollisionSystem）、スコア計算・ランキング集計（RankingManager）、SNSシェア文生成（ResultShare）などの純粋なロジックは描画層から分離し、Vitest で自動テストを回せる構造にしています。 ドメイン移行やバランス調整を行ってもコアロジックが壊れていないことを即座に確認できるため、個人開発でも安心して改修を続けられます。
