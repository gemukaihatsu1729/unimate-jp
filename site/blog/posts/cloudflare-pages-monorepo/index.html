Cloudflare Pages Vite モノレポ

独自ドメイン＋Cloudflare Pages モノレポで複数ブラウザゲームを統合運用する構成

公開日: 2026-11-21 カテゴリ: インフラ・サイト運用

個人でブラウザゲームを複数作っていくと、最初はゲームごとに別々の GitHub リポジトリと GitHub Pages で公開するのが手軽です。 しかし作品数が増えて独自ドメインへ移行し、ポートフォリオやブログもまとめて発信したくなると、URL構造や共通ページの管理が課題になってきます。

1. なぜ /games/ 配下のモノレポ構成にしたのか

Unimate JP では、次のような階層構造でコンテンツを整理しています。 

unimate-jp.com/
├── /                  （総合トップ）
├── /games/            （ゲームポータル・遊び方ガイド）
│   ├── mousoutero/
│   ├── zonbi/
│   └── flashanzan/
├── /portfolio/        （制作ポートフォリオ）
├── /blog/             （個人開発・技術ブログ）
└── /privacy/, /about/, /contact/

この構造にすることで、ゲーム同士の回遊がしやすくなるだけでなく、将来のブログ記事やポートフォリオ作品もすべて 1 つのドメイン資産として積み上げられるメリットがあります。

2. npm workspaces で各ゲームの独立性を保ちながら一括ビルド

リポジトリ内は site/（トップ・ポータル・ブログ等）と games/*（個別の Vite ゲームプロジェクト）に分割し、ルートの package.json で npm workspaces を有効化しています。

  • 各ゲームの vite.config.ts は base: './' を維持しているため、サブディレクトリ配下でもアセット参照が壊れない
  • 開発時は npm run dev:mousoutero のように単体ゲームだけ軽量に起動できる
  • デプロイ時はルートで npm run build を実行すると、site/ と games/* の全ビルド成果物が自動的に dist/ と dist/games/<slug>/ に統合される

3. Cloudflare Pages を選んだ理由

静的サイトの配信先には Cloudflare Pages を採用しました。GitHub リポジトリと連携しておけば main ブランチへプッシュするだけで自動ビルド＆デプロイが走り、エッジCDNによる高速配信と自動HTTPSが無料枠で利用できます。 また、Xserver ドメイン側のネームサーバーを Cloudflare へ向けることで、www なしのルートドメイン（unimate-jp.com）もスムーズに割り当てられるのが大きな利点です。

4. 新しいゲームや記事を追加する手順のシンプルさ

新しいゲームを追加したいときは games/<新しいゲーム名>/ に Vite プロジェクトを置き、ポータルページに紹介カードを追加するだけで自動ビルド対象になります。 ブログ記事も site/blog/posts/<記事スラッグ>/index.html を追加すれば Vite のマルチページ検出によって自動でビルドされるため、制作そのものに集中できる環境が整いました。 （最終的には wrangler.jsonc を配置し、Cloudflare 公式推奨の Workers Static Assets 構成で運用しています。）
