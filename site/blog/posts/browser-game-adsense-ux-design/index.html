ブラウザゲームの広告配置と誤クリック防止設計：600ms遅延・ボタン間150px・CLSゼロを実装した理由

公開日: 2026-11-21 カテゴリ: インフラ・UI設計

スマートフォンのフルスクリーンブラウザゲームを運営して広告収益化を目指すとき、最も避けなければならないのが「ゲーム操作と広告の距離が近すぎて誤クリック（誤タップ）を誘発してしまうこと」です。 プレイヤーにとってストレスになるだけでなく、Google AdSense のポリシー上も「ゲームプレイ中の領域や操作ボタンの直近への配置」は厳しく見られます。

そこで Unimate JP では、公開中の3つのゲームすべてに共通の安全設計スクリプト /common/js/result-ad.js を組み込み、「遊ぶ体験を守ること」と「クリーンな広告表示」を両立させる構造にしました。

1. プレイ画面には広告を一切置かず、リザルト画面の上部のみに限定

3D無双アクションの移動スティックや攻撃ボタン、フラッシュ暗算の親指テンキーが表示されているプレイ中は、広告要素を一切表示しません。 広告スロットを配置するのは、プレイが完全に終了して開く「リザルト画面／ゲームオーバーモーダル」内の最上部のみです。

さらに、広告スロットの直下に「共有ボタン」や「リトライボタン」を置くのではなく、間に「ランクスタンプ」「総合スコア」「戦績サマリー」を挟むレイアウトにしました。これにより、広告下端から最初の操作ボタンまで 250px〜350px 以上（推奨基準の 150px 以上を余裕でクリア）の距離を確保しています。

2. 「連打の誤タップ」と「レイアウトズレ」を同時に防ぐ CSS + JS 設計

ゲーム終了直後は、プレイヤーが直前まで画面を連打しているケースが少なくありません。そこで次の2つを組み合わせています。

  • 事前領域確保（CLSゼロ）：.result-ad に最初から min-height: 118px（ラベル 16px ＋ バナー 100px）の高さを確保し、広告が後から読み込まれてもスコアやボタンが下にガクッとズレないようにしています。
  • 600ms の表示遅延：IntersectionObserver と MutationObserver でリザルト画面の表示を検知したあと、最初の 600ms 間は visibility: hidden; pointer-events: none; の状態を維持し、600ms 経過後に is-ready クラスを付けてタップ可能にしています。
// リザルトが開くたびに 600ms のガード時間を設ける
showTimer = window.setTimeout(function () {
  if (shown && !isElementHidden(hostScreen)) {
    container.classList.add('is-ready');
  }
}, 600);

3. 1ページ滞在につき1回だけロードし、リトライ時にリフレッシュしない

「もう一度遊ぶ」でリトライして再びリザルト画面を開いた際、毎回新しい広告をリクエストし直す実装は、ポリシー違反（不正な自動リフレッシュ）とみなされるリスクがあります。 result-ad.js ではコンテナ単位で loaded フラグを持ち、adsbygoogle.push({}) は初回表示時の 1 回だけ実行し、2回目以降のリザルト表示では 600ms 遅延の保護のみを再適用する安全な設計にしています。

4. 審査前・ローカル開発・本番を環境変数で自動切替

審査通過前やスロットID未設定の段階で、画面上に「空白の枠」や「広告」という文字だけが表示されてしまうと UX を損ねます。 そのためビルドスクリプト（scripts/build-all.mjs）と連携し、次のように環境ごとに自動分岐させています。

  • 審査中・スロットID未設定の本番：モードは disabled となり、DOM上も hidden のまま完全に非表示（余白もゼロ）。
  • ローカル開発（localhost / ?adpreview=1）：点線の 320×100 プレビュー枠が出現し、600ms 遅延やスクロール挙動を確認可能。
  • 本番運用（環境変数設定後）：スロットIDとパブリッシャーIDが自動注入され、重複読み込みを防ぎながら固定サイズ 320×100 ユニットを描画。
